# Command line

Every command is `qdw <group> <action>`; `--help` on any of them prints the same information. This page is generated by `tools/gen_cli_docs.py`.

## qdw cp2k

CP2K PBE track.

### qdw cp2k prepare

Input, geometry and job script for one step.

```text
qdw cp2k prepare [-h] --step {geo_opt,pdos,trexio,sample,charges}
                        --project PROJECT --out OUT [--cluster CLUSTER]
                        [--wfn WFN] [--window WINDOW] [--charge CHARGE]
                        [--optimizer OPTIMIZER] [--data-dir DATA_DIR]
                        [--time TIME] [--qos QOS]
                        xyz
```

| Argument | Meaning | Default |
|---|---|---|
| `xyz` | structure (XYZ) |  |
| `--step` | which CP2K step |  |
| `--project` | CP2K project name (file prefix) |  |
| `--out` | output directory |  |
| `--cluster` | cluster profile (clusters/<name>.yaml or a path) | `default` |
| `--wfn` | geo_opt restart file read by the later steps |  |
| `--window` | window.json from `qdw cp2k window` (trexio step) |  |
| `--charge` | total charge | `0` |
| `--optimizer` | geo_opt: auto (LBFGS above 1,000 atoms), BFGS or LBFGS | `auto` |
| `--data-dir` | local copy of the CP2K data files (default: $QDW_CP2K_DATA, then the cluster path) |  |
| `--time` | wall time, overriding the cluster profile (e.g. 00:10:00) |  |
| `--qos` | QoS, overriding the cluster profile (e.g. test) |  |

### qdw cp2k chain

One job for geo_opt, PDOS, window, TREXIO and trim.

```text
qdw cp2k chain [-h] --project PROJECT --out OUT [--cluster CLUSTER]
                      [--charge CHARGE] [--optimizer OPTIMIZER]
                      [--data-dir DATA_DIR] [--record RECORD] [--time TIME]
                      [--qos QOS]
                      xyz
```

| Argument | Meaning | Default |
|---|---|---|
| `xyz` | MACE-relaxed structure |  |
| `--project` | CP2K project name (file prefix) |  |
| `--out` | output directory of the chain |  |
| `--cluster` | cluster profile | `default` |
| `--charge` | total charge | `0` |
| `--optimizer` | geo_opt optimiser: auto (LBFGS above 1,000 atoms), BFGS or LBFGS | `auto` |
| `--data-dir` | local copy of the CP2K data files (default: $QDW_CP2K_DATA, then the cluster path) |  |
| `--record` | record.json of the structure; adds QDEX as the last step |  |
| `--time` | wall time of the whole chain |  |
| `--qos` | QoS, overriding the cluster profile |  |

### qdw cp2k window

MO window from the pdos step.

```text
qdw cp2k window [-h] [-o OUTPUT] [--below BELOW] [--above ABOVE]
                       pdos [pdos ...]
```

| Argument | Meaning | Default |
|---|---|---|
| `pdos` | the pdos step's .pdos files |  |
| `-o, --output` | window.json to write |  |
| `--below` | eV below the valence band edge | `5.0` |
| `--above` | eV above the conduction band edge | `5.0` |

### qdw cp2k trim

```text
qdw cp2k trim [-h] --window WINDOW src dst
```

| Argument | Meaning | Default |
|---|---|---|
| `src` | TREXIO .h5 from the trexio step |  |
| `dst` | trimmed .h5 to write |  |
| `--window` | window.json from qdw cp2k window |  |

### qdw cp2k esp

Solvation cubes: intact and fully stripped dot, monomers -> COSMO (solvation.json).

**`qdw cp2k esp prepare`**: The runs, from the chain's single-point input (field/base/cp2k.inp).

```text
qdw cp2k esp prepare [-h] [--stripped STRIPPED] [--monomers MONOMERS]
                            base out
```

| Argument | Meaning | Default |
|---|---|---|
| `base` | the chain's single-point input (field/base/cp2k.inp) |  |
| `out` | directory of the esp runs |  |
| `--stripped` | fully stripped dot: props/detach_<K>.xyz |  |
| `--monomers` | props/monomers.xyz (frames MA, MX) |  |

**`qdw cp2k esp status`**: "all done" or the runs still to do.

```text
qdw cp2k esp status [-h] dir
```

| Argument | Meaning | Default |
|---|---|---|
| `dir` | directory of the esp runs |  |

**`qdw cp2k esp collect`**: COSMO energy and isosurface area of every run.

```text
qdw cp2k esp collect [-h] -o OUTPUT dir
```

| Argument | Meaning | Default |
|---|---|---|
| `dir` | directory of the esp runs |  |
| `-o, --output` | solvation.json to write |  |

## qdw qdex

QDEX on the TREXIO orbitals.

### qdw qdex prepare

Config.yaml from the record and the MO window.

```text
qdw qdex prepare [-h] --window WINDOW --out OUT [--cluster CLUSTER]
                        [--orbitals ORBITALS] [--geom GEOM]
                        [--threads THREADS] [--max-states MAX_STATES]
                        record
```

| Argument | Meaning | Default |
|---|---|---|
| `record` | record.json of the dot |  |
| `--window` | window.json from qdw cp2k window |  |
| `--out` | QDEX run directory |  |
| `--cluster` | cluster profile | `default` |
| `--orbitals` | TREXIO file, relative to --out | `../orbitals.h5` |
| `--geom` | geometry, relative to --out | `../relaxed.xyz` |
| `--threads` | OpenMP threads for QDEX | `8` |
| `--max-states` | occupied and virtual MOs in the sBSE, at most (default 1000) |  |

### qdw qdex summary

Frontier levels, gaps and excitons (spin-free and SOC) as JSON.

```text
qdw qdex summary [-h] [-o OUTPUT] [--bright-f BRIGHT_F] dir
```

| Argument | Meaning | Default |
|---|---|---|
| `dir` | QDEX run directory (qdex_electronic.h5, qdex_excitations.h5) |  |
| `-o, --output` | JSON file to write (default: print) |  |
| `--bright-f` | oscillator strength of the first bright exciton | `0.05` |

### qdw qdex webapp

Webapp.json: summary, band-edge excitons and absorption spectra.

```text
qdw qdex webapp [-h] [-o OUTPUT] [--window WINDOW] dir
```

| Argument | Meaning | Default |
|---|---|---|
| `dir` | QDEX run directory |  |
| `-o, --output` | webapp.json to write |  |
| `--window` | band-edge states up to this far above the lowest (eV) | `0.5` |

## qdw props

Orchestr.AI PROPS runs on a GPU cluster.

### qdw props prepare

Config.yaml and GPU job script for a set of records.

```text
qdw props prepare [-h] --out OUT [--cluster CLUSTER] [--steps STEPS]
                         [--max-atoms MAX_ATOMS] [--time TIME] [--qos QOS]
                         [--name NAME] [--pieces] [--md] [--cpu-time CPU_TIME]
                         records [records ...]
```

| Argument | Meaning | Default |
|---|---|---|
| `records` | record directories (record.json + start.xyz) |  |
| `--out` | job directory |  |
| `--cluster` | cluster profile | `default` |
| `--steps` | comma-separated steps (default: all) |  |
| `--max-atoms` | records above this many atoms are left out (default 2,000) |  |
| `--time` | wall time of the GPU job |  |
| `--qos` | QoS, overriding the cluster profile |  |
| `--name` | job name | `props` |
| `--pieces` | resubmit the job until the run finishes (short QoS) |  |
| `--md` | also run MD (constant-T and ramp replicas): the MD subset |  |
| `--cpu-time` | wall time of the CPU (assembly) stage, if the profile splits the run |  |

### qdw props chains

One CP2K chain (geo_opt, field, PDOS, TREXIO, QDEX) per record at <record>/cp2k.

```text
qdw props chains [-h] [--config CONFIG] [--cluster CLUSTER]
                        [--max-atoms MAX_ATOMS] [--submit] [--time TIME]
                        [--qos QOS]
                        [records ...]
```

| Argument | Meaning | Default |
|---|---|---|
| `records` | record directories |  |
| `--config` | a PROPS config.yaml whose props.records are used |  |
| `--cluster` | cluster profile | `default` |
| `--max-atoms` | records above this many atoms get no chain | `2000` |
| `--submit` | sbatch each chain; prints the job ids |  |
| `--time` | wall time of each chain |  |
| `--qos` | QoS, overriding the cluster profile |  |

### qdw props bench

GPU job timing force calls and Hessians against the atom count.

```text
qdw props bench [-h] --out OUT [--cluster CLUSTER] [--sizes SIZES]
                       [--time TIME] [--qos QOS] [--extra EXTRA]
```

| Argument | Meaning | Default |
|---|---|---|
| `--out` | job directory |  |
| `--cluster` | cluster profile | `default` |
| `--sizes` | atom counts of the benchmark spheres | `100,300,1000,2000,5000` |
| `--time` | wall time | `01:00:00` |
| `--qos` | QoS, overriding the cluster profile |  |
| `--extra` | more orchestr_ai.qd.bench options, e.g. '--analytic-max 1000' | `` |

## qdw reaction

Reaction free energies vs T, eps and concentrations.

### qdw reaction check

Read the reaction file: balance, units, dE_DFT.

```text
qdw reaction check [-h] reaction
```

| Argument | Meaning | Default |
|---|---|---|
| `reaction` | reaction.yaml |  |

### qdw reaction prepare

Run directory: MACE (GPU), CP2K (CPU) and analysis jobs, submit.sh.

```text
qdw reaction prepare [-h] --out OUT [--cluster CLUSTER]
                            [--gpu-time GPU_TIME] [--cpu-time CPU_TIME]
                            [--qos QOS] [--data-dir DATA_DIR] [--test-queue]
                            reaction
```

| Argument | Meaning | Default |
|---|---|---|
| `reaction` | reaction.yaml |  |
| `--out` | run directory |  |
| `--cluster` | cluster profile | `default` |
| `--gpu-time` | wall time of the MACE (GPU) job | `01:00:00` |
| `--cpu-time` | wall time of the CP2K job (default: estimated from the largest species) |  |
| `--qos` | QoS, overriding the cluster profile |  |
| `--data-dir` | local copy of the CP2K data files (default: $QDW_CP2K_DATA, then the cluster path) |  |
| `--test-queue` | all jobs in the test partitions (1 h); CP2K in pieces that resubmit themselves |  |

### qdw reaction analyse

Results/: results.json, summary.json, plots, reaction.html.

```text
qdw reaction analyse [-h] run
```

| Argument | Meaning | Default |
|---|---|---|
| `run` | run directory |  |

## qdw compare

Compare two props/properties.json (Phase 0 gate).

```text
qdw compare [-h] [--rtol RTOL] [--show SHOW] ref new
```

| Argument | Meaning | Default |
|---|---|---|
| `ref` | reference properties.json |  |
| `new` | properties.json to compare |  |
| `--rtol` | relative tolerance for values without an absolute one | `0.001` |
| `--show` | show at most this many differences | `30` |
